# OpenAI Realtime API統合 要件定義書

## 1. エグゼクティブサマリー

現在モック音声ファイル（001.wav〜005.wav）を使用してコンサルタント対話デモを提供しているConsultantDetailPage.tsxを、OpenAI Realtime APIと統合し、リアルタイムの音声対話システムに変換する。これにより、より自然で動的なコンサルタント体験を提供し、ユーザーの質問に対してリアルタイムで適切なコンサルタント回答を生成する。

## 2. 機能要件

### 2.1 音声入出力

#### 2.1.1 音声入力
- **WebSocket音声ストリーミング**: リアルタイムでマイク音声をOpenAI APIにストリーミング
- **音声検出機能（VAD）**: 話し始めと終了の自動検出
- **ノイズキャンセレーション**: 環境ノイズの軽減（可能な範囲で）
- **音声品質最適化**: 16kHz サンプリングレート、16-bit PCM形式での送信
- **マイク権限管理**: ブラウザのマイクアクセス許可の適切な処理

#### 2.1.2 音声出力
- **リアルタイム音声再生**: OpenAI APIからのストリーミング音声をリアルタイムで再生
- **音声バッファリング**: スムーズな再生のための適切なバッファリング
- **音量制御**: ユーザーが音量を調整可能
- **音声停止機能**: ユーザーが途中で音声を停止可能
- **音声品質維持**: 明瞭で聞き取りやすい音声出力

### 2.2 WebSocket接続管理

#### 2.2.1 接続確立
- **セキュア接続**: wss://プロトコルを使用した安全な接続
- **認証**: APIキーを使用した適切な認証
- **接続タイムアウト**: 10秒以内での接続確立
- **再接続機能**: 接続失敗時の自動再接続メカニズム

#### 2.2.2 接続維持
- **ハートビート**: 定期的なping/pongでの接続確認
- **接続状態監視**: リアルタイムでの接続ステータス表示
- **エラーハンドリング**: 接続エラー時の適切な処理とユーザー通知

### 2.3 会話管理

#### 2.3.1 セッション制御
- **セッション初期化**: コンサルタントペルソナの設定
- **会話開始**: ウェルカムメッセージの自動生成
- **会話継続**: 自然な対話の流れの維持
- **セッション終了**: 適切な終了処理とリソース解放

#### 2.3.2 会話フロー統合
- **既存フェーズの維持**: questions → hot-reading → cold-reading → subsidies → summary → recommendations
- **動的フェーズ遷移**: ユーザーの回答に基づく柔軟なフェーズ変更
- **コンテキスト保持**: 会話全体を通じた情報の継続性
- **フォールバック機能**: API障害時のモック音声への自動切り替え

### 2.4 コンサルタントペルソナ

#### 2.4.1 キャラクター設定
- **専門知識**: 補助金・助成金に関する専門的知識
- **話し方**: 丁寧で親しみやすい口調
- **業界理解**: IT業界、製造業への深い理解
- **実務経験**: 実際のコンサルティング経験に基づく回答

#### 2.4.2 応答スタイル
- **構造化回答**: 論理的で整理された回答構成
- **具体例提示**: 実際の事例を交えた説明
- **次のステップ**: 明確な行動指針の提示
- **確認質問**: 理解度を確認する適切な質問

### 2.5 エラー回復

#### 2.5.1 接続エラー
- **自動再接続**: 最大3回までの自動再接続試行
- **フォールバックモード**: モック音声への自動切り替え
- **エラー通知**: ユーザーへの分かりやすいエラーメッセージ
- **手動再試行**: ユーザーによる手動再接続オプション

#### 2.5.2 音声エラー
- **音声品質劣化**: 品質低下時の自動調整
- **音声途切れ**: バッファリングエラーの処理
- **遅延対応**: レスポンス遅延時のタイムアウト処理

## 5. ユーザーストーリー

### 5.1 基本的な音声コンサルテーション

**As a** ユーザー  
**I want to** マイクボタンをクリックして音声で質問する  
**So that** 自然な対話形式でコンサルタントと相談できる

**受け入れ基準:**
- マイクボタンをクリックすると音声録音が開始される
- 話し終わると自動的に録音が停止される
- 3秒以内にコンサルタントの音声応答が開始される
- 応答内容が文字としてもチャット履歴に表示される

### 5.2 会話の中断と再開

**As a** ユーザー  
**I want to** 必要に応じて音声を停止または中断する  
**So that** 緊急時や集中したいタイミングで対話をコントロールできる

**受け入れ基準:**
- 音声再生中に停止ボタンで音声を止められる
- 通話ボタンで会話セッションを一時停止できる
- 再開時に会話のコンテキストが保持されている

### 5.3 接続エラー時の対応

**As a** ユーザー  
**I want to** インターネット接続に問題があってもサービスを利用する  
**So that** 通信環境に関係なく一貫した体験を得られる

**受け入れ基準:**
- 接続エラーが発生するとモック音声に自動切り替えされる
- エラー状況がユーザーに分かりやすく表示される
- 接続が回復すると自動的にリアルタイムモードに戻る

### 5.4 会話履歴の確認

**As a** ユーザー  
**I want to** これまでの会話内容をテキストで確認する  
**So that** 重要な情報を見返したり、次のステップを確認できる

**受け入れ基準:**
- 音声のやり取りがすべてテキスト化されてチャット履歴に表示される

### 5.5 モバイルでの利用

**As a** モバイルユーザー  
**I want to** スマートフォンでも音声コンサルテーションを利用する  
**So that** 場所を選ばずにコンサルタントに相談できる

**受け入れ基準:**
- タッチスクリーンで直感的に操作できる
- モバイルブラウザでマイク権限が適切に取得される
- 画面サイズに応じてレイアウトが最適化される
- 音声品質がデスクトップと同等に保たれる

## 8. 制約と前提

### 8.1 技術的制約

#### 8.1.1 API制限
- OpenAI Realtime APIの料金制約（高コスト）
- APIレート制限（1時間あたりのリクエスト数）
- 同時接続数の制限（プランによる）
- 音声ファイルサイズの制限

#### 8.1.2 ブラウザ制限
- マイク権限取得の必要性
- HTTPSでの動作必須
- モバイルブラウザでの制限事項
- WebSocket接続の安定性

### 8.2 ビジネス制約

#### 8.2.1 運用コスト
- 音声処理による高額なAPI料金
- 通信量に応じた従量課金
- サーバーリソースの増加

#### 8.2.2 法的・規制要件
- 個人情報保護法への準拠
- 音声データの取り扱いルール
- 海外APIサービス利用時の規制

### 8.3 前提条件

#### 8.3.1 環境要件
- OpenAI APIキーの取得済み
- HTTPS環境でのデプロイ
- 適切なCORS設定

#### 8.3.2 ユーザー環境
- モダンブラウザの使用
